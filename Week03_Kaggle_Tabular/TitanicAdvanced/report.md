# Titanic 生存预测项目周报


## 1. 问题定义

### 1.1 项目背景
本项目为 Kaggle 经典竞赛 **Titanic: Machine Learning from Disaster** 的实战演练。该竞赛提供了泰坦尼克号乘客的数据集，包含乘客的个人信息——姓名、性别、年龄、舱位等级、票价、登船港口等。目标是预测每位乘客在海难中是否幸存（Survived: 0 表示遇难，1 表示幸存）。

### 1.2 问题类型
这是一个典型的**监督式二分类问题**。训练集包含 891 个样本，测试集包含 418 个样本。评价指标为**准确率（Accuracy）**，即预测正确的样本占总样本的比例：

$$\\text{Accuracy} = \\frac{TP + TN}{TP + TN + FP + FN}$$

### 1.3 项目目标
- 构建一个能够在测试集上达到较高准确率的分类模型
- 完成至少 4 种不同算法的模型训练与对比
- 通过特征工程和模型融合提升预测精度
- 完成至少 2 次 Kaggle 提交，验证模型泛化能力

---

## 2. 探索性数据分析（EDA）

### 2.1 目标变量分析
首先对目标变量 `Survived` 进行分布分析。训练集显示，共有 891 名乘客，其中 **342 人幸存（38.4%）**，**549 人遇难（61.6%）**。数据存在轻微的不平衡，但尚未达到需要特殊处理的程度。

### 2.2 缺失值分析
对训练集和测试集的缺失值进行了系统检查。发现以下特征存在缺失：

| 特征 | 训练集缺失数 | 测试集缺失数 | 缺失含义 |
|------|-------------|-------------|----------|
| Age | 177 | 86 | 年龄未知 |
| Cabin | 687 | 327 | 无船舱记录 |
| Embarked | 2 | 0 | 登船港口未知 |
| Fare | 0 | 1 | 票价未知 |

其中 `Cabin` 缺失率超过 77%，但缺失本身具有业务含义——无船舱记录可能代表该乘客未分配固定舱位或位于低等级区域。因此，处理策略是不直接使用该列，而是从中提取“是否有船舱”和“甲板号”等衍生特征。

### 2.3 相关性分析
通过可视化分析，发现与生存率关联最强的特征包括：

| 特征 | 与生存率的关系 |
|------|---------------|
| Sex（性别） | 女性生存率约 74%，男性仅约 19% |
| Pclass（舱位等级） | 头等舱生存率约 63%，三等舱仅约 24% |
| Age（年龄） | 儿童（<12岁）生存率较高 |
| Fare（票价） | 生存者票价中位数显著更高 |
| FamilySize（家庭规模） | 中等家庭（2~4人）生存率最高 |

这表明**性别、社会阶层、年龄和家庭结构**是决定生死的关键因素。

## 3. 数据预处理与特征工程

### 3.1 缺失值处理
| 特征类型 | 处理方式 | 特征示例 |
|----------|----------|----------|
| Age（年龄） | 按 Title（称谓）分组填充中位数 | Mr, Mrs, Miss, Master |
| Fare（票价） | 填充中位数 | 测试集 1 个缺失 |
| Embarked（登船港口） | 填充众数（'S'） | 2 个缺失 |

### 3.2 类别编码
全部类别特征转换为数值型：
- `Sex`：male → 0, female → 1
- `Embarked`：S → 0, C → 1, Q → 2

### 3.3 新特征构造
基于对 Titanic 沉船场景的理解，构造了以下新特征：

| 新特征 | 构造公式 | 业务含义 |
|--------|----------|----------|
| `Title` | 从 `Name` 中提取称谓（Mr/Mrs/Miss/Master 等）映射为数值 | 反映社会地位和年龄 |
| `FamilySize` | `SibSp` + `Parch` + 1 | 家庭总人数 |
| `IsAlone` | 1 若 `FamilySize` == 1，否则 0 | 是否独行 |
| `FamilyGroup` | 将 `FamilySize` 分为 4 档 | 区分独行/小/中/大家庭 |
| `HasCabin` | 1 若 `Cabin` 非空，否则 0 | 是否有固定舱位 |
| `Deck` | 从 `Cabin` 提取首字母（A~G，缺失为 U） | 船舱所在甲板层 |
| `AgeBin` | 年龄分 5 箱：`[0,12),[12,20),[20,35),[35,60),[60,100]` | 捕获年龄的生存非线性效应 |
| `FareBin` | 票价按四分位数分箱 | 减轻离群值影响 |
| `FareLog` | `log(1 + Fare)` 对数变换 | 处理票价长尾分布 |

这些组合特征将分散的属性整合为更具预测力的指标，其中 `Title` 和 `FamilySize` 对生存率的区分度尤为显著——拥有贵族头衔或处于中等家庭的乘客生存概率明显更高。

### 3.4 删除冗余列
以下列在提取有效信息后予以删除：
- `Name`（已提取 Title）
- `Ticket`（数据过于稀疏且模式复杂）
- `Cabin`（已提取 HasCabin 和 Deck）

经过以上处理，最终特征维度为 15 列（含目标变量），训练集和测试集均无缺失值。

## 4. 模型选择与训练

### 4.1 基模型
共选用了 4 种不同的分类算法作为基模型：

| 模型 | 类型 | 特点 |
|------|------|------|
| **Logistic Regression** | 线性模型 | 简单高效，作为性能基准 |
| **Random Forest** | 集成树（Bagging） | 并行训练，可解释性强，不易过拟合 |
| **XGBoost** | 梯度提升树 | 效率高，内置正则化，抗过拟合强 |
| **LightGBM** | 梯度提升树 | 基于直方图，训练速度快，内存占用低 |

### 4.2 超参数优化
使用 **GridSearchCV**（网格搜索）对 Random Forest 和 XGBoost 进行 5 折交叉验证调优：

**Random Forest 调优参数**：
- `n_estimators`: [100, 200, 300]
- `max_depth`: [5, 10, 15]
- `min_samples_split`: [2, 5, 10]
- `min_samples_leaf`: [1, 2, 4]

**XGBoost 调优参数**：
- `n_estimators`: [100, 200]
- `max_depth`: [3, 5, 7]
- `learning_rate`: [0.01, 0.05, 0.1]
- `subsample`: [0.8, 1.0]
- `colsample_bytree`: [0.8, 1.0]

### 4.3 模型性能对比
各模型在 5 折交叉验证上的准确率表现如下：

| 模型 | CV 平均准确率 | 标准差 |
|------|--------------|--------|
| Logistic Regression | 0.806 | 0.019 |
| Random Forest（调优后） | 0.821 | 0.022 |
| XGBoost（调优后） | 0.831 | 0.020 |
| LightGBM | 0.827 | 0.023 |

可以看到，XGBoost 和 LightGBM 在本次任务中表现最佳，而 Logistic Regression 作为线性基准模型性能相对有限，这暗示了特征与目标之间可能存在非线性关系。

## 5. 模型融合

### 5.1 Stacking 集成策略
为进一步提升性能，采用 **Stacking** 策略对所有基模型进行集成。具体流程如下：

1. 使用调优后的 **Random Forest、XGBoost、LightGBM** 作为基学习器
2. 使用 5 折交叉验证，为每个基模型生成训练集的预测概率（作为元特征）
3. 将全部元特征拼接，形成新的训练集
4. 使用 **Logistic Regression** 作为元模型，学习如何最佳地组合各基模型的预测

### 5.2 集成效果
Stacking 集成在交叉验证上的准确率达到 **0.837**，显著优于任何单一模型。这说明不同模型的预测误差之间存在互补性，集成学习能够有效地综合利用各模型的优势。

## 6. Kaggle 提交与结果

### 6.1 提交策略
采用两种不同的预测策略：

| 提交类型 | 文件名 | Public Score | 说明 |
|----------|--------|-------------|------|
| 第一次提交 | `titanic_submission_v1.csv` | **0.77272** | Stacking 集成策略（3 基模型 + Logistic Regression 元模型） |
| 第二次提交 | `titanic_submission_v2.csv` | **0.77033** | 调优后的 XGBoost 单模型策略 |

### 6.2 结果分析
- **Stacking 集成模型**取得了 0.77272 的 Public Score，优于单模型策略。
- **XGBoost 单模型**取得了 0.77033 的 Public Score，验证了优化后代码的基础性能。
- Stacking 集成相比 XGBoost 单模型提升了约 **0.31%**（0.77272 - 0.77033），验证了集成策略的有效性——不同模型的预测误差存在互补性，集成学习能够有效提升模型的泛化能力。
- 交叉验证分数（~0.837）与 Kaggle Public Score（~0.772）存在差距，说明训练集与 Public LB 的样本分布存在差异，也可能存在轻微过拟合。

## 7. 错误分析与改进方向

### 7.1 当前不足
- 部分年轻男性（三等舱）被误判为生存，而实际未存活，可能与缺乏职业或具体家庭关系信息有关。
- 年龄极端值（如婴幼儿或高龄老人）预测准确率较低，可能因样本量不足。
- Cabin 信息虽提取了 Deck（甲板号），但贡献有限，信息利用率仍有提升空间。
- 交叉验证分数（~0.837）与 Kaggle Public Score（~0.772）存在差距，说明模型泛化能力仍有提升空间。

### 7.2 可优化方向
1. **更精细的特征工程**：从 `Ticket` 提取团体人数，或构建“家庭平均生存率”等交叉特征。
2. **模型调优深化**：使用 Optuna 或 BayesSearch 进行更高效的超参数搜索。
3. **深度学习尝试**：使用 TabNet 或简单 MLP 神经网络捕捉高阶交互关系。
4. **更复杂的集成策略**：Blending 或使用不同折数的 Stacking。
5. **特征重要性分析**：使用 SHAP 值筛选最优特征子集，减少过拟合。

## 8. 总结

### 8.1 核心收获
通过本次 Kaggle 竞赛项目的实战，我深刻认识到：
- **EDA 是建模的基石**：只有充分理解数据分布和特征含义，才能做出有效的预处理决策。例如，`Cabin` 虽缺失严重，但提取 `HasCabin` 后仍带来正向收益。
- **特征工程决定性能上限**：优质的组合特征（如 `FamilySize`、`Title`）和对数变换（`FareLog`）带来的提升，往往远超模型调参的收益。
- **集成学习是提升精度的利器**：Stacking 策略能够有效融合不同模型的优点，获得更稳健的预测，尤其当基模型差异较大时效果更明显。
- **交叉验证分数 ≠ 在线分数**：CV 分数（~0.837）与 Public LB（~0.772）的差距提醒我，模型泛化能力的评估需要结合多种手段，不能过度依赖单一切分方式。

### 8.2 项目成果

| 基模型数量 | 4 个（Logistic Regression, Random Forest, XGBoost, LightGBM） |

| 超参数调优 | GridSearchCV 对 RandomForest 和 XGBoost 进行 5 折交叉验证调优 |
